# 学习通/泛雅课程结构分类（实测：示例课程 <courseId>）

> 本文档是根据真实账号抓包 + 接口探测整理的**结构分类**，不是猜测。
> 目的：区分"章节"和"任务中心"，以及每个入口里每一种任务点的**完成规则**和**上报接口**。

## 一、两个互相独立的学习入口

| | 章节（目录） | 任务中心（教学任务） |
| --- | --- | --- |
| 入口 | 课程页「章节」tab | 课程页「首页」→ 任务中心 |
| 数据接口 | `mooc2-ans/mycourse/studentcourse`（老版 HTML 目录） | `mooc2-ans/fanya3/s/taskSignupList` |
| 层级 | 章 → 任务点卡片 | 教学任务 → 分组（顺序解锁）→ 任务点(plan) |
| 完成任务的方式 | `mooc-ans/knowledge/cards` 拿卡片，按类型完成 | `task.chaoxing.com` 任务引擎自己的学习页 |
| 是否互通 | **不互通**：两边是两套独立的学习记录与入口 | |

同一个课程可以只有章节、只有教学任务，或者两者都有；教师强调哪种方式，学生就必须走哪种。

## 二、章节里的任务点卡片类型（`knowledge/cards` → mArg.attachments）

| 卡片 type | 说明 | 程序处理 |
| --- | --- | --- |
| `video` | 视频（音频任务也走这里，失败后回退 Audio） | ✅ 已有的 mooc 视频播放逻辑 |
| `document` | 文档/PPT，走 `/ananas/job/document` | ✅ |
| `read` | 阅读任务，走 `/ananas/job/readv2` | ✅ |
| `workid` | 章节测验（要答题） | ✅ 需要题库；没题库会明确跳过 |
| `live` | 直播任务 | ✅ |
| （空章节） | 没有任务点 | ✅ 补一次访问 |

**2026-09 平台改动**：`knowledge/cards` 只有 `num=0` 那一页带完整 mArg，`num>=1` 的页面变成了
`mArg = $mArg;`（脚本注入，页面里没有 JSON）。旧代码在第一页之后解析失败就整章判失败，
导致新版课程"一个任务点都读不到"。现在改成：**逐页解析，解析不出就跳过，一页都解析不出才算读取失败**。

## 三、任务中心 → 教学任务 → 任务点类型与完成规则（实测 planBreakthroughSet）

| planType | 名称 | 完成规则字段（示例值） | 人话 |
| --- | --- | --- | --- |
| 10 | 视频 | `enableVideoComplated=1` | 播完即可 |
| 10 | 视频 | `enableVideoWatchDuration=1, videoWatchDuration=2.0` | **累计观看 2 分钟** |
| 11 | 文档 | `enableDocumentWatchDuration=1, documentWatchDuration=5.0` | **累计阅读 5 分钟** |
| 11 | 文档 | `enableCompleteRead=1` | 还要"读到底"（readEnd） |
| 8 | 章节 | `enableChapterFinishPercent=1` | 对应章节点全部任务点完成 |
| 4 | 作业 | `enableWorkScore=1` | 作业要有得分（2026-09-20 实测：判 83.3 分后 `isFinish=true`） |
| 9 | 思考题 | 无特殊规则 | 提交回答 |
| 14 | 主题讨论 | `enableReplyDiscuss=1` | 要回复讨论 |
| 15 | AI实践 | `enableAicoach=1` / `enableFinishAicoach=1` | 完成 AI 对话 |

分组解锁条件（`getGroupData.groupAllowStudyCondition`）常见文案：
- `所有任务点闯关完成；每个视频完成观看`
- `每篇文档完成阅读`
- `完成AI对话`
- `需完成上个分组`

**顺序解锁是硬约束**：上一组没做完，`getToStudyUrl` 直接返回 `任务点未解锁，不允许学习`。

## 六、"真实学习时间"的实测结论

1. **视频有时长要求时不能加速**：同一个视频 2 倍速打点只按一半计入，原地发心跳完全不计。
   所以有 `enableVideoWatchDuration` 的视频必须 1 倍速真实播放；一遍不够要回看。
2. **只有"播完"要求的视频**可以用配置里的倍速（平台按"是否到结尾"判定）。
3. **文档必须按节奏打点**：阅读器每 30 秒上报一次，服务端据此累计阅读时长；
   2/5/10 分钟的要求只能靠真实时间堆出来，没有捷径。
4. 完成判定有延迟：打点够了之后任务点状态要等一会儿才变，程序里要留等待+复查。

## 八、AI实践（思维阶梯 / think-ladder）实测接口

AI实践任务点的入口：`/ai-evaluate/v2/answer?...&publishRelationUuid=...&__from=taskEngine`，
会 302 到 SPA：`/mooc2-ans-vue/think-ladder/answer/pc-index?...&aiEnc=...`。

已实测可用的接口（都在 `mooc2-ans.chaoxing.com` 下）：

| 接口 | 方法 | 参数 | 作用 |
| --- | --- | --- | --- |
| `/mooc2-ans/ai-evaluate/v2/answer/init` | POST(form-urlencoded) | courseid / clazzid / cpi / publishRelationUuid / type=2 | 开始一次作答，返回 answerUuid、recordUuid |
| `/mooc2-ans/ai-evaluate/v2/answer/load-data` | GET | courseid / clazzid / cpi / publishRelationUuid | 题目、要求、维度列表(dimensionList)、历史作答记录、当前 answerScore、答案数上限 |
| `/ai-ans/ai-evaluate/think/main-talk` | POST(SSE) | courseId / clazzId / cpi / aiEnc / recordUuid / isPreview / newAnswerView；body: `userMessage=...` | 学生发一条 → AI 流式回复下一个问题/点评 |
| `/ai-ans/ai-evaluate/think/change-question` | POST(SSE) | 同上 | 让 AI 换一道题 |
| `/mooc2-ans/ai-evaluate/v2/answer/submit` | POST(form-urlencoded) | courseid / clazzid / cpi / recordUuid | 结束本次作答（**不会**出分，见下） |
| `/ai-ans/ai-evaluate/think/end-report` | POST(SSE) | courseId / clazzId / cpi / aiEnc / recordUuid | **现算并返回成绩**：SSE 第一帧就是 `{"id":"score","content":"100"}` |
| `/mooc2-ans/ai-evaluate/v2/answer/evaluate-result` | GET | 同上 + personId | 评估报告正文（知识点解析 + 每个维度的亮点/不足） |

### 出分机制的坑（2026-09-17 实测）

1. **提交 ≠ 出分**：`answer/submit` 之后平台**不会自动评估**。实测提交后等 10 分钟，
   `answerRecords` 里仍然没有这条记录（`scoreCount` 不涨）。页面上那句
   "以下是根据您的学习情况生成的质量评估报告，请点击下方「学习质量评估报告」查看"
   对应的就是 `think/end-report`：**学生点一次，平台才现算一次成绩**。
   CLI 现在提交后立刻请求一次 `end-report`，成绩随即回填到 `answerRecords`。
2. **成绩字段的口径**：页面写的达标标准是"学生多次练习平均分达到 N 分"
   （`publishSetting.scoreType=2`，i18n 里 2 对应"多次作答时取最高分"，
   两条文案互相矛盾），而实测 `load-data` 顶层 `answerScore` 在
   `[30, 60, 100]` 三条记录下等于 **100**，即**最高分/最后一次**，不是平均分。
   代码里两者都看齐：单次成绩和练习平均分都到目标线才算达标。
3. **判分是平台自己的大模型，会自相矛盾**：同一道单选，标准答案选项被判"回答错误"，
   换一个选项才"回答正确"；判断题答"错"被判错、答"对"又被判错的情况也出现过。
   因此重试要换一个没试过的选项，且必须限次。
4. **局不会自己结束**：知识点全部答完（`unCompleteTopic: []`）后，平台还会把最后一道
   题推回来，而 `messageList` 不再增长（作答根本没被收录）。实测这样空转十几轮，
   本地"错/对"来回换。判据：`unCompleteTopic` 空 + 连续两次作答没有新消息 → 提交收手。
5. **一次练习 = 一遍全部知识点**（本项目 9 个），全部答对给满分：9 道全对的记录拿到 100 分，
   评估报告写"所有题目作答全部正确…无作答错误"；只有 1 道题就提交的那次只有 30 分。

实测到的状态样例（企业战略管理·开学第一课，6 次练习后）：
`answerScore: 100.0`、`answerRecords: [100, 100, 100, 100, 60, 30]`（平均 81.7）、
`answerCount: 6`、`scoreCount: 6`、`remainAnswerCount: 94`（上限 100 次）。

> 结论：AI实践的"高分重答"链路已按真实平台验收：大模型生成回答（`api/ai_writer.py`）
> → `main-talk` 逐轮作答（选择题/判断题只发字母或对错）→ 提交门禁 → `submit`
> → `end-report` 现算成绩 → 读回 `answerScore`/平均分 → 不够就再 `init` 一次重答。
> 2026-09-17 真机：4 次练习 100 分，练习平均分 81.7，任务 `userTaskQualifyStatus=已达标`。

## 十、为什么很多任务快不了

- 视频有时长要求时服务端按真实时间扣减，**2 倍速只算一半**，原地心跳不计数 → 只能按 1 倍速真实播放，不够就回看。
- 文档要求"阅读 2/5/10 分钟"，是服务端按阅读器打点累计的，没有加速通道。
- 任务引擎的分组是闯关式的：上一组没完成，`getToStudyUrl` 直接拒绝，无法跳级。
