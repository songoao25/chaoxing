# 任务中心适配计划

## 目标

把「任务中心 → 教学任务」接入现有命令行程序，做到：

1. 能自动处理的视频、文档、章节、作业、讨论、思考题和 AI 实践，按平台真实规则执行；
2. 每个任务都经过“接口结果 + 任务状态复查”双重确认，失败、锁定和暂不支持都明确显示；
3. 任务中心失败不影响原有章节刷课，网络抖动可以从当前进度继续；
4. 真实时长严格按平台要求执行，不加速、不伪造心跳、不并发轰炸。

## 每项适配的固定流程

1. 先读取当前任务点和分组，不猜测未解锁接口。
2. 只对当前可学的一项取证；请求、响应和页面变量全部脱敏保存。
3. 先写 FakeSession/FakeTC 离线测试，再改实现。
4. 真实验证只做当前任务点，按平台时间间隔执行，不并发、不重复刷同一资源。
5. 以任务中心重新读取的 `isFinish` / `planUser.finish` 作为唯一完成依据。
6. 更新 `TASKS.yaml`、`SESSION-LOG.md` 和必要的交接说明，留下下一步第一动作。

## 当前决策门

- 只要平台返回“参数信息有误”或“enc不正确”，该请求就视为失败；HTTP 200 不等于任务完成。
- `cap-autopull` 已 ✅；章节同步只认平台下发的 `stuJobInfo`（决 D11），拿不到就报"未同步"，不伪造 `enc`。
- 视频打点遇到 403 时先用 curl 原样重放（决 D12）；进度到结尾但未通过时从头回看（决 D13）。
- 文档时长 A 已暂停真实重跑，避免重复消耗学习时间；最终验收必须看到任务中心状态变为完成。

## 日常运行入口

```bash
make doctor    # 环境与数据目录
make status    # 只读任务中心状态
make classify  # 只读平台结构抽样
make lint      # 编译检查 + 全量离线测试
./cx --yes     # 真实学习；只有在前置验证通过后执行
```

对使用者只需要记住：先看 `make status`，再运行 `./cx --yes`；程序会跳过已完成项，遇到锁定或不支持的任务会报告原因，不会把跳过显示成完成。
